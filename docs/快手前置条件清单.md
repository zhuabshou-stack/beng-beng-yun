# 快手小游戏前置条件清单（备查，暂缓实施）

> 整理时间：2026-09-14。依据快手开放平台官方文档（open.kuaishou.com/miniGameDocs）当日内容核实。
> 结论：**快手小游戏目前仅支持企业主体入驻，个人开发者无法上架**，故 v2.10.0 暂缓快手渠道。以下为日后启动所需的全部前置条件与既有技术结论。

## 一、硬性前置条件（官方确认）

| 条件 | 说明 |
|---|---|
| 企业主体 | 开发者账号需企业入驻（个体户/公司营业执照）；`open.kuaishou.com/miniGameDocs/operation/specification/qualifications.html` |
| 软著 | 《计算机软件著作权登记证书》，且著作权人需与接入主体名称完全一致，不一致需授权证明 |
| 自审自查报告 | 上线前需提供 |
| 小游戏作品备案申请表 | 上线前需提供 |
| 商标注册证书 | 如有则提供 |

## 二、技术路线（已核实，日后直接复用）

- Cocos Creator 3.8 **没有内置快手构建目标**；快手官方推荐路径：
  1. 用引擎的**微信小游戏导出**入口打出微信包；
  2. 用「快手小游戏开发者工具」导入该包；
  3. 工具内开启「设置 → 本地配置 → 自动适配微信小游戏」，自动生成 `kwaiadapter.js` 并在 game.js 引入，运行时模拟 wx 对象。
- 快手原生 API 在 `ks` 命名空间；工程 `PlatformService` 已预留 `kuaishou` 平台判定（`typeof ks !== 'undefined'`），当前快手上分享等能力走 `WechatBridge`（依赖 kwaiadapter 模拟 wx），与官方推荐一致。
- 官方提醒：模拟 wx 不覆盖全部开放 API，上架前需真机回归；避免 `if (wx)` 裸判断逻辑（本工程已通过 PlatformService 收敛，无裸判断）。

## 三、启动时要做的事

1. 注册企业主体快手开放平台账号，创建小游戏拿到快手 AppID。
2. 安装快手小游戏开发者工具，导入 `build/wechatgame`，开自动适配，验证分享/震动/存档。
3. 提交资质：软著（著作权人主体对齐）+ 自审自查报告 + 备案申请表。
4. 真机回归后走快手审核上架。

## 四、与抖音/微信的差异备忘

- 快手官方 API 列表未见开放数据域/好友关系链类 API → 好友排行能力（如未来做）在快手端不可用或需替代方案。
- 本地排行榜、震动、分享等本工程已用能力，在快手端均有对应实现（wx 模拟或 ks 原生）。
